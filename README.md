# Next.js на Татнет: Полка разработчика

Открытый пример Next.js App Router: каталог инструментов с серверным рендерингом,
поиском, фильтрами, страницами карточек и JSON API. Без базы данных, секретов,
внешних API и загрузки шрифтов с Google. Код можно использовать как шаблон.

## Запуск локально

Нужны Node.js 22+ и Bun 1.4+. Версии Next.js и React зафиксированы в `package.json`,
зависимости — в `bun.lock`.

```sh
git clone https://github.com/tatnet-ru/nextjs-example.git
cd nextjs-example
bun install --frozen-lockfile
bun run dev
```

Откройте <http://localhost:3000>. Проверка production-сборки:

```sh
bun test
bun run build
bun run typecheck
bun run start
```

## Деплой на Татнет из GitHub

1. Сделайте fork репозитория в свой аккаунт GitHub.
2. В [панели Татнет](https://min.tatnet.ru/) создайте проект или выберите существующий.
3. Создайте приложение, подключите GitHub и выберите свой fork, ветку `main`.
4. Проверьте фреймворк `Next.js`, корень проекта — корневая папка, версию Node.js — 22 или 24.
   Команда установки — `bun install --frozen-lockfile`, команда сборки — `bun run build`,
   каталог результата — `.next`. Переменные окружения для этого примера не нужны.
5. Запустите деплой. После сборки откройте адрес приложения с HTTPS из панели.

В `next.config.ts` явно указан `output: "standalone"`. `output: "export"` здесь
не подходит: главная страница использует сервер на каждом запросе.

Альтернатива — [CLI Татнет](https://tatnet.ru/cli). После авторизации и выбора проекта:

```sh
tatnet deploy . --name my-nextjs-demo --framework nextjs
```

CLI загрузит локальные исходники. Это отдельный способ публикации: он не подключает
автоматические обновления из GitHub. Для Git-деплоя настройте приложение из репозитория.

## Что проверять после деплоя

Замените `YOUR_APP_URL` на выданный платформой HTTPS-адрес:

```sh
curl -fsS 'YOUR_APP_URL/api/health'
curl -fsS 'YOUR_APP_URL/api/tools?q=React'
curl -fsS 'YOUR_APP_URL/tools/nextjs'
```

- На главной меняются время и ID серверного ответа при обновлении страницы.
- Поиск `React` находит Next.js; категория «Данные» — PostgreSQL и Valkey.
- Фильтры находятся в URL: ссылкой на результат можно поделиться.
- `/api/tools` возвращает JSON с теми же фильтрами, `total`, `generatedAt` и `requestId`.
- Два запроса к API дают разные `requestId`; заголовок `Cache-Control: no-store`
  запрещает кэширование ответа API.
- `/tools/nextjs` открывается напрямую; неизвестный адрес карточки возвращает 404.

## Как устроен пример

| Файл | Назначение |
| --- | --- |
| `app/page.tsx` | Серверный компонент; `connection()` требует рендеринг на запрос |
| `app/tools/[slug]/page.tsx` | Страница инструмента с собственной metadata |
| `app/api/tools/route.ts` | Route Handler с фильтрацией и `no-store` |
| `app/api/health/route.ts` | Проверка готовности приложения |
| `lib/catalog.ts` | Данные и общая фильтрация для страницы и API |
| `tests/catalog.test.ts` | Поиск, неизвестные фильтры и контракт API |

Форма — обычный HTML GET: каталог работает и с отключённым JavaScript.
Клиент не обращается к API ради первого отображения — сервер сразу отдаёт готовый HTML.
Серверный компонент и Route Handler импортируют общую функцию, без HTTP-запроса
приложения к самому себе.

## Стоимость и границы примера

Плата состоит из выбранного тарифа Apps и потребления ресурсов сверх включённого
объёма. Актуальные цены и лимиты — на [странице тарифов](https://tatnet.ru/pricing).
Свой домен и preview зависят от тарифа. При scale-to-zero первый запрос после
простоя может ждать запуска приложения.

Пример проверяет SSR, App Router, Route Handlers и Node.js runtime. Он не является
нагрузочным тестом и не доказывает поддержку всех возможностей Next.js. Здесь нет
авторизации, загрузки файлов, Server Actions, базы, постоянного кэша или ISR.
Если добавляете запись данных, используйте внешнюю БД или хранилище: файловая
система экземпляра не заменяет постоянное хранилище.
